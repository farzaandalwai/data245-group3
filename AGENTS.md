# Repository instructions

- Start from a short bounded human request; orientation alone does not authorize implementation. Read local and fetched main context, [approved protocol](docs/experiment_protocol.md), [interfaces](docs/interfaces.md), [ownership](docs/team_responsibilities.md), and relevant owner README before proposing changes. No repeated starter-prompt paste is required.
- At task start, meaningful checkpoints and before publication: inspect status/branch/remotes, fetch origin, compare fetched base, review relevant changes and open issues/PRs. Never blindly pull into dirty work. If remote access fails, mark shared state potentially stale and avoid publishing overlaps.
- Resolve human identity with authenticated GitHub and the confirmed context map, not Git author settings. Active owners: DELTA (data/features/baselines), DEVGRU (linear/ridge), SAS (tree/evaluation). Preserve imported authorship; historical five-person assignments are not active. The full-name mapping for `shoddy16` remains unconfirmed.
- Normal implementation uses separate clones and distinct `<codename>/<task>` branches from current main; concurrent sessions use separate worktrees. Never switch another session's branch. Explicit task constraints override default Git workflow. The current authorized DELTA implementation includes data/features/baselines/tests/docs in this checkout; no staging, commit, push or merge. Stage resolutions only if an actual merge is unresolved; do not invent a merge or finalize a merge commit.
- Record owner, branch, files, dependencies and acceptance before implementation. Recheck overlapping work; claims/context are not locks. No custom locking service or teammate assignments without agreement. Coordinate before editing another owner's implementation or shared contracts.
- Scientific precedence is defined once in the protocol: protocol > interfaces > responsibilities > YAML metadata > context > experiment log > other READMEs > archive. This file governs agent workflow. Flag contradictions; do not silently change targets, samples, features, population or splits. Approved amendments update protocol, affected metadata/docs and experiment log.
- Distinguish APPROVED, PROPOSED, PENDING VERIFICATION, DRAFT CONTRACT, NOT IMPLEMENTED, IMPLEMENTED and HISTORICAL. Unimplemented documentation is not executable functionality. Inherited pilot results are never new final results. Identify experiment version and development/final purpose on every artifact.
- DELTA supplies the centralized shared data/features. Preserve identical observation keys/actuals/splits across feature conditions, model families and baseline comparisons. Model owners must not independently redefine the data/evaluation contract.
- Use past-only history and explicit predictor allowlists. Never use target-day stockout information as a predictor; it is retrospective evaluation metadata. IDs are keys, not automatically approved features. Follow train-only preprocessing, validation-only tuning and test isolation; disclose known historical test exposure.
- Preserve byte-identical originals in `archive/original_pilot/`, original handoff/prompts, canonical pilot/manifests and inherited results. Never edit archival evidence during active changes. Never commit raw CSVs or secrets, even with `git add -f`. Keep new/reproduction outputs separate. Do not run legacy notebooks/scripts as setup.
- No deep learning or unrelated experiments. Missing new samples/models/results are expected. No invented authorship, AI co-author trailers, completed work or sustainability findings. Save substantive prompts in `docs/prompts/`; unknown model versions stay unknown.
- For substantive authorized commits, update context (including integration status), contributions and AI records; inspect staged files, use small commits and task PRs. Never discard/reset/clean others' edits, auto-stash them, force-push shared branches or merge without human instruction. Resolve context conflicts semantically; integrate PRs one at a time after review, then fetch/reread.
- Final handoff: changed files, actual checks/results, blockers, branch/PR and next action. Individual reports reflect actual student contributions and distinct prose.
- Active contract registration is `configs/contract.yaml` (producer v2.0.0 implemented; broader technical contract DRAFT). Read [DELTA handoff](docs/DELTA_DATA_HANDOFF.md) for verified bundle paths, operational/provisional semantics and consumer commands. `docs/history/contract_v1/` is immutable historical evidence, never V2 authority; keep V1 reproduction tests separate from active checks.
