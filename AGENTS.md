# Repository instructions

- This file is the automatic project startup guidance. Do not require humans to paste `starter_prompt.md` or repeat these rules. For each new task, perform the startup checks below from a short human request. “Get me oriented” means orientation only; “continue my task” means resume an unambiguous, previously recorded task after checking current state. If the task is unclear, orient and suggest a bounded next task.
- Active owners: DELTA (data/features/baselines), DEVGRU (linear/ridge), SAS (tree/evaluation/integration). Identity mapping is in `context.md`; preserve real imported authorship in provenance. Follow `docs/team_responsibilities.md` and `docs/interfaces.md`. Only these three are active; other names in the archived handoff are historical.
- Scope each session to the human's bounded task. If no task is supplied, orient and suggest one; do not start remaining experiments automatically. Setup ends after migration.
- Git provides versioned collaboration, not live shared memory. `context.md` or issue assignment cannot guarantee another session is idle. Use no custom locking service.
- At task start, meaningful long-task checkpoints, and before final push: inspect status/branch/remotes; fetch origin; read these instructions, `git show origin/main:context.md`, local context, relevant changes, and open issues/PRs. Compare against the last fetched base. Never blindly pull into dirty work.
- If remote access fails, mark shared state potentially stale. Continue isolated safe local inspection, but do not publish overlapping changes until coordination returns.
- Resolve human identity through authenticated GitHub and the confirmed map, not Git author settings alone. Each human uses a separate clone. Each task uses a distinct `<codename>/<task>` branch (DELTA, DEVGRU, SAS) from current main; concurrent sessions on one computer use separate worktrees. Never switch branches under another session. The full-name mapping for `shoddy16` remains unconfirmed.
- Before implementation, record owner, branch, files, dependencies, and acceptance criteria in an issue or context. Recheck overlapping issues/PRs; claims are not locks. Do not assign teammates work without agreement.
- For an existing task branch, inspect and merge `origin/main` when safe. Never discard edits, reset/clean destructively, auto-stash others' work, or force-push shared branches. Resolve meaningful conflicts against the protocol while preserving both contributors' valid work.
- Implement only the assigned task. Coordinate before editing another member's model/notebook except for an agreed dependency or verified bug. Keep data, feature, and prediction interfaces documented.
- Preserve byte-identical originals in `archive/original_pilot`, attribution, the canonical pilot in `data/processed`, manifest/exclusions in `data/manifests`, and inherited results in `results/baselines_DELTA/inherited`. Working legacy copies have adapted paths and separate reproduction destinations; do not run them as part of setup. Never commit the raw CSV or secrets, even with `git add -f`.
- Follow `docs/experiment_protocol.md`: past-only predictors, explicit allowlist, identical eligible target keys, training-only preprocessing, validation-only tuning, and honest test exposure. Stockout semantics/eligibility remain unverified until the next authorized contract task. No deep learning or scope inflation.
- Distinguish inherited, inspected, executed, verified, missing, and pending evidence. Never present planned models, unexecuted notebooks, unmerged work, or inherited numbers as independently completed. Sustainability benefits are unmeasured.
- With each substantive task commit update `context.md`, showing branch work pending integration, and applicable contribution/AI records. Save substantive prompts under `docs/prompts/`; unknown model versions stay unknown. Do not fabricate authorship or AI co-author trailers.
- Make small commits; inspect each staged file. Push the task branch and open a PR. Do not merge without human instruction. Before merge, the human integrator reviews diff, latest main, checks, overlaps, and context; resolve context conflicts semantically and merge one PR at a time. Afterwards all dependent sessions fetch and reread context.
- Final handoff: changed files, checks actually run and results, blockers, branch/PR, next action. Individual reports must reflect each student's actual contributions and distinct prose.
