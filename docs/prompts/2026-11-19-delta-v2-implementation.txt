# 2. Approved research design — NONNEGOTIABLE

## Research question

Does adding historical stockout information improve next-day fresh-food recorded-sales forecasts compared with using sales history alone?

We predict normalized recorded `sale_amount`, not latent customer demand.

## Dataset

FreshRetailNet-50K project export.

Historical development sample: 200 complete store-product series.

Final experiment: 1,000 complete store-product series.

Use a reproducible, documented selection process.

Preserve the existing 200-series development manifest exactly.

## Primary population

Use ALL otherwise eligible target dates, including dates with stockouts.

Do not filter targets based solely on target-day stockout hours.

## Secondary evaluation

Separately evaluate predictions on:

- Fully stocked target days.
- Target days with stockouts.

These are evaluation groups, not separately trained models.

Target-day stockout status must never be a model predictor.

## Historical features

Maximum lookback: 14 days.

Sales-only predictors:

1. `sales_lag_1`
2. `sales_lag_2`
3. `sales_lag_3`
4. `sales_lag_7`
5. `sales_lag_14`
6. `sales_mean_7`
7. `sales_mean_14`
8. `weekday`
9. `is_weekend`

Stockout-aware predictors: the same nine predictors plus:

10. `stockout_hours_lag_1`
11. `stockout_hours_mean_7`
12. `stockout_hours_mean_14`
13. `stockout_day_fraction_7`
14. `stockout_day_fraction_14`

All lags and rolling statistics use only historical dates strictly before the target date.

Store/product identifiers are keys, not predictors.

Do not introduce weather, promotions, categorical ID predictors, or additional features into the approved primary experiment.

## Chronological split

For each complete 90-day series:

- Days 1–60: train.
- Days 61–75: validation.
- Days 76–90: test.
- First eligible target: day 15.

With no additional quality exclusions, expected development counts are 9,200 training, 3,000 validation, and 3,000 test targets.

Expected final counts are 46,000 training, 15,000 validation, and 15,000 test targets.

These counts are expectations that must be verified, not fabricated outputs.

## Models and evaluation

DELTA owns:

- Persistence baseline.
- Previous 7-day mean baseline.

DEVGRU owns Linear Regression and Ridge.

SAS owns Decision Tree, optional Random Forest, and common model evaluation.

MAE is primary. RMSE and signed prediction bias are secondary.

Do not implement DEVGRU or SAS model-training code in this task.
