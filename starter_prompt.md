# Reusable session starter

After accepting the invitation, clone `https://github.com/farzaandalwai/data245-group3.git` into your own local folder and open it in Codex. Each human pastes the following with a bounded task or `orientation only` on the last line. Use a separate worktree for concurrent sessions on one computer.

```text
Work in this repository under its AGENTS.md instructions.

First inspect the working tree, branch, and remote. Fetch origin without
discarding local changes. Read the latest origin/main context.md and relevant
merged changes, then the local context and any open issue/PR touching my task.
Compare with the last fetched base. Repeat these checks at meaningful
checkpoints and before final push; do not blindly pull into dirty work.
If the network is unavailable, state that shared state may be stale and avoid
publishing overlapping changes until coordination is restored.

Resolve my identity from the authenticated GitHub account; do not infer it
from Git author settings alone. Use my own task branch/worktree, starting a
new task branch from current main. For an existing branch, inspect and merge
origin/main when safe. Briefly state completed and pending work, any overlap,
and the bounded task you are taking. Record its owner, branch, files,
dependencies, and acceptance criteria before implementation. An issue claim
is not an atomic lock; recheck overlap and do not assign others without agreement.
If I have not given a task, orient me and suggest the next bounded task;
do not start the remaining project automatically.

Preserve the fixed series manifest, chronological splits, past-only feature
timing, matched eligible row sets, stable interfaces, and teammate attribution.
Read docs/experiment_protocol.md. Target-day availability is eligibility
metadata only; its semantics and indexing still need formal verification.
Use an explicit predictor allowlist. Never overwrite imported baselines or
run imported preparation entry points without a separate authorized plan.
Coordinate before changing another member's model/notebook. Never discard,
destructively reset/clean, or auto-stash others' work or force-push shared branches.

Make only necessary changes, run relevant checks, update context.md with each
substantive commit and applicable contribution/AI records, fetch again,
inspect upstream changes, and push a small task branch with a PR.
Keep unmerged branch work visibly pending integration. Do not merge without
my instruction. A human integrator reviews latest main, the diff, checks,
overlaps, and context, then merges one PR at a time. Preserve both valid
context updates in conflicts; other sessions fetch and reread after merge.

Git is versioned collaboration, not live shared memory. Reading context or
claiming an issue cannot guarantee other sessions are idle. Do not build
custom distributed locks. State exactly what was inherited, verified, run,
missing, pending, or unmerged. End with changed files, checks/results,
blockers, branch/PR, and next action. Individual reports require actual
personal contributions and distinct prose.

My task for this session: [describe the bounded task, or say orientation only].
```
